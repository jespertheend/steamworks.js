# AGENTS.md

Instructions for AI coding agents working in this repository.

## Commands

- Requirements: node, rust, clang and a running Steam client (init() throws
  without one, tests and manual scripts too). The first build needs network
  access because the rust dependency is fetched from git
- `npm run build:debug`: debug napi build, what you want for local dev
- `npm run build`: types generation plus release build (includes lto), what
  CI uses
- Both write `dist/<target folder>/steamworksjs.<platform>.node` and copy
  the matching steam_api redist library out of `sdk/redistributable_bin`
- `npm run types`: emits index.d.ts from index.js with tsc
- `npm run prune`: deletes dist, target and client.d.ts
- `npm run format`: cargo clippy --fix plus cargo fmt, rust side only
- Validation before finishing: `cargo fmt --all --check` and
  `cargo clippy` must pass, publish.yml runs both.
- There is no JS test framework. `test/*.js` are manual scripts run with
  node after building (need Steam running, they use app 480), and
  test/electron is a manual electron harness (`npm install && npm start`
  inside it), mostly for overlay testing

## Generated code

- `client.d.ts`: generated by the napi build from the #[napi] definitions
  in src/, output location configured in build.js. It is committed on
  purpose since it is the published type surface, regenerate it with a
  build, never edit by hand
- `index.d.ts`: generated from index.js by `npm run types`
- `callbacks.d.ts`: hand written callback payload types. Payloads cross
  the boundary as serde_json values, so the types must describe runtime
  values rather than rust field types: napi turns integers up to
  +/-(2^53-1) into number, anything beyond that into bigint. Typed
  napi signatures (everything outside of callback payloads) are exact
  by construction. rust enums serialize as their variant name strings,
  which match the values of napi string enums exported in client.d.ts
  (so a payload field typed with an enum from the rust side maps to
  that const enum here)
- `sdk/redistributable_bin` (the steam_api redist libraries) is committed,
  the rest of sdk/ is gitignored. dist/ and target/ are build output

## Repository context

- Fork of https://github.com/ceifa/steamworks.js. `origin` points to
  https://github.com/jespertheend/steamworks.js, `upstream` to cefa's
- Cargo.toml pins the `steamworks` crate to a `rev` of the
  jespertheend/steamworks-rs fork. Make rust side changes in that repo
  first and push them there, then bump `rev` here to the pushed SHA (full
  40 characters). Commit Cargo.toml together with Cargo.lock: the lock
  updates itself on the first cargo build after the bump, cargo
  re-resolves the git dependency
- Releasing is opt-in: publish.yml attempts an npm publish on every push
  to main, so a version bump in package.json reaching main is what
  releases a new version. Don't bump the version unless a release is
  explicitly asked for. Without a bump the publish job fails on the
  duplicate version, that's expected and nothing gets published
- This package's client.d.ts is parsed downstream by steam-web-wrap to
  generate its enum glue from a hardcoded list of method signatures. If
  that generator throws, its parser needs updating, see its AGENTS.md

## Architecture

- napi-rs native module: src/lib.rs exposes init, restartAppIfNecessary and
  runCallbacks, src/client.rs holds the client singleton, src/api/<topic>.rs
  define the #[napi] functions that make up the JS api
- napi converts rust snake_case fn names to camelCase in client.d.ts and at
  runtime (run_frame becomes runFrame)
- index.js loads the platform specific binary from dist/, starts the
  runCallbacks interval (30hz) on init and re-exports SteamCallback
- Types flow one way: rust signatures behind #[napi] generate client.d.ts,
  index.js adds its own JSDoc types on top

## Style

- Rust: rustfmt plus clippy clean
- JS/TS: there is a .prettierrc (single quotes, no semicolons, 4 space
  width, 140 print width), not enforced in CI but keep new code consistent
- Keep code comments short, only for non-obvious intent
